# ADR-0001: Двухуровневый конвейер детекции (детерминированный слой + модель по требованию)

## Status

Accepted

## Context

Переключатель раскладки живёт на горячем пути ввода. Решение принимается на границе токена, то
есть десятки раз в минуту, в процессе, который обязан быть незаметным: бюджет — единицы
миллисекунд, фон — почти нулевой CPU, память — десятки мегабайт, иначе продукт удалят вне
зависимости от качества детекции.

Одновременно (см. `docs/product/vision.md`) весь смысл проекта — снять класс ошибок, который
недоступен словарной эвристике: технический и смешанный текст, имена собственные, короткие
токены. Это требует контекста, то есть модели.

Два требования конфликтуют напрямую: модель, вызываемая на каждый токен, съедает бюджет
латентности и батареи; модель, не вызываемая никогда, не даёт продукту причины существовать.

Важное свойство задачи: **альтернативная гипотеза получается детерминированно**. Раскладка —
это обратимое посимвольное отображение, поэтому по набранному токену всегда однозначно
восстанавливается его вариант в другой раскладке. Генерация кандидатов бесплатна; дорогой
является только оценка.

Второе важное свойство: **стоимость ошибок асимметрична**. Ложное переключение разрушает
доверие, пропущенное — исправляется пользователем за секунду.

## Decision

Конвейер разделяется на два уровня, разделённых порогом уверенности.

**Tier 0 — детерминированный, всегда.**
Карта раскладок порождает альтернативу токена. Обе гипотезы оцениваются дешёвым локальным
скорером (символьная n-граммная модель для каждого языка плюс частотный словарь). Если разрыв
между гипотезами превышает верхний порог — решение принимается здесь и модель не вызывается.
Бюджет: суб-миллисекунда, единицы мегабайт.

**Tier 1 — контекстная модель, по требованию.**
Вызывается только в зоне неуверенности Tier 0. Получает не голый токен, а окно контекста:
предыдущие слова, их языки, класс активного приложения. Возвращает решение с уверенностью.
Бюджет: десятки миллисекунд, асинхронно относительно ввода.

**Порог по умолчанию смещён в сторону молчания.** При неуверенности обоих уровней действие —
не переключать.

Tier 1 закрыт интерфейсом `LayoutDecider` с одной операцией «контекст → решение + уверенность»,
чтобы конкретная модель менялась без изменения остальной системы. Выбор этой модели — предмет
[ADR-0002](./ADR-0002-model-selection-for-context-disambiguation.md), и он намеренно отложен:
архитектура не должна его ждать.

## Consequences

- Латентность продукта определяется Tier 0 и не зависит от того, какая модель окажется в
  Tier 1. Плохой выбор модели ухудшит качество на сложных случаях, но не сделает продукт
  тормозящим.
- Tier 0 можно измерять и поставлять раньше Tier 1: это самостоятельный работающий
  переключатель уровня Punto Switcher, и одновременно baseline, относительно которого любая
  модель обязана доказать прирост.
- Доля обращений к Tier 1 становится наблюдаемой метрикой: она напрямую задаёт энергопотребление
  и подсказывает, где Tier 0 слаб.
- Плата: два скорера вместо одного и необходимость калибровать пороги на размеченном корпусе.
- Асимметричные пороги гарантированно снижают recall. Это принято сознательно.

## Alternatives Considered

- **Только словарь и n-граммы (модель Punto Switcher).** Дёшево и предсказуемо, но не решает
  ту задачу, ради которой проект начат.
- **Только модель, на каждый токен.** Простая архитектура, неприемлемый бюджет: инференс
  трансформера на каждое слово — это постоянная нагрузка на CPU в фоновом процессе, который
  пользователь не запускал осознанно.
- **Отложенная пакетная коррекция** (анализировать предложение целиком после его завершения).
  Дешевле по вызовам модели, но пользователь к этому моменту уже видит мусор на экране; это
  меняет продукт с «переключателя» на «автокорректор».
