# ADR-0005: Персонализация и дообучение на пользователе

## Status

Accepted

## Context

Разбор ошибок Sprint 1 показал, что остаток ошибок Tier 0 сосредоточен в коллизиях — наборах
нажатий, осмысленных в обеих раскладках (`руку`/`here`, `луны`/`keys`, `ТЗ`/`NP`). Их разрешение
зависит от того, о чём человек вообще пишет. Ответ для верстальщика и для биолога разный, и
никакая обученная на общем корпусе модель этого не знает.

Отсюда требование: **модель должна дообучаться на конкретном пользователе в процессе работы.**
Сигнал для этого уже есть и уже предусмотрен — отмена автопереключения одной клавишей
(ADR-0003). Каждая отмена это размеченный пример: «здесь ты ошибся».

Требование напрямую сталкивается с [ADR-0003](./ADR-0003-windows-input-interception.md), где
записано: *«Ввод не сохраняется на диск никогда. Контекст живёт в оперативной памяти в пределах
окна из нескольких последних токенов и перезаписывается»*, и с принципом локальности из
`docs/product/vision.md`.

Конфликт настоящий, а не формальный. Персонализация требует, чтобы что-то пережило перезапуск
процесса. Вопрос в том, **что именно** переживает.

Второе ограничение — форма модели. Дообучение на потоке отмен возможно только у модели,
допускающей обновление по одному примеру. Трансформерный энкодер такого не допускает в принципе:
дообучать `multilingual-e5-small` на пользовательской машине по одной правке нереалистично ни
по вычислениям, ни по устойчивости.

## Decision

Персонализация принимается как требование первого порядка, а не как возможное расширение.
Из неё следуют четыре ограничения.

### 1. Сохраняются веса и счётчики, но не текст

На диск попадают только числа: веса линейной модели и частотные счётчики. Ни одного фрагмента
набранного текста, ни одного токена в исходном виде.

Это ослабляет формулировку ADR-0003 и требует честной оговорки: **частотные счётчики не являются
безобидными.** Словарь «слова, которые этот человек набирает часто» — это данные о пользователе,
даже если сами слова не образуют связного текста. Поэтому:

- счётчики хранятся только для токенов, участвовавших в **ошибочном** решении, то есть для тех,
  где пользователь нажал отмену, а не для всего набранного;
- файл персонализации лежит в профиле пользователя и не покидает машину ни при каких условиях;
- в продукте есть команда «забыть всё», удаляющая его целиком.

ADR-0003 подлежит правке: абсолютное «никогда» заменяется на «текст ввода — никогда; производные
веса — только по описанным здесь правилам».

### 2. Tier 1 — линейная модель над признаками Tier 0

Форма модели выбирается под возможность обновления по одному примеру:

- десятки весов, а не миллионы;
- обновление — один шаг градиента, микросекунды;
- признаки берутся у Tier 0, который их уже посчитал: отрыв гипотез, длина токена, регистр,
  решение соседей, оценка контекста;
- модель интерпретируема, то есть по весам видно, чему она научилась.

Это же снимает вопрос латентности: Tier 1 перестаёт быть отдельным дорогим вызовом.

### 3. Обучение стартует с общей модели, а не с нуля

Пользователь не должен обучать переключатель с чистого листа. В дистрибутив входят веса,
обученные на общем корпусе; персонализация начинается от них и сдвигает их постепенно.
Скорость обучения ограничена сверху, чтобы одна случайная отмена не ломала поведение.

### 4. Персонализация обязана быть обратимой

Дообучение может увести модель в худшую сторону — на редких или случайных отменах. Поэтому:

- исходные веса всегда сохраняются рядом и доступны для отката;
- продукт не удаляет возможность вернуться к поставочному поведению.

## Consequences

- Кандидат `multilingual-e5-small` из
  [ADR-0002](./ADR-0002-model-selection-for-context-disambiguation.md) слабеет ещё до замера:
  он не удовлетворяет требованию дообучения. Он может остаться источником **признаков** для
  линейной модели, но не решающим слоем.
- Появляется артефакт на диске, которого раньше в архитектуре не было, и вместе с ним — вопросы
  миграции формата и порчи файла.
- Разработка усложняется: онлайн-обучение нужно уметь тестировать, а его дефекты проявляются
  только со временем.
- Метрика качества раздваивается: качество на общем корпусе и качество после N персональных
  правок — разные величины, и вторую пока нечем мерить.

## Alternatives Considered

- **Только словарь исключений, без обучения** (уже запланирован в Sprint 4). Проще и безопаснее,
  но запоминает конкретные токены и не обобщает: научившись на `луны`, ничего не узнаёт про
  `швы`. Остаётся как дополнение, не как замена.
- **Дообучение нейросетевой модели на устройстве.** Отвергнуто: нереалистично по вычислениям и
  неустойчиво на единичных примерах.
- **Сбор правок на сервере и общая переобученная модель.** Отвергнуто безусловно: нарушает
  локальность из `docs/product/vision.md`. Именно эти данные — то, что пользователь набирает, —
  не должны покидать машину.

## Open Questions

- Сколько персональных правок нужно, чтобы качество заметно сдвинулось? Пока нечем измерить.
- Как отличить «пользователь исправляет нашу ошибку» от «пользователь передумал»? Обе выглядят
  как отмена.
- Нужна ли отдельная модель на приложение? Терминал и мессенджер — разные регистры текста у
  одного человека.
- Формат файла весов и его миграция между версиями.
